Theory

Connect 4. Two players drop discs into a 7×6 grid. The first to line up four in a row (horizontally, vertically or diagonally) wins. Each position has up to 7 moves, so looking d moves ahead means up to 7d positions. A full search is far too large, so the AI stops at a fixed depth.

Minimax. The AI (MAX) picks the move with the highest score, assuming you (MIN) always reply with the move that is worst for the AI. Scores are backed up from the leaves of the search tree to the root.

Depth limit and heuristic. At depth 0 the game is usually undecided, so the AI estimates the position with an evaluation function: windows of four cells with 3 of its own discs and one empty cell score well, the same for the opponent scores badly, and discs in the centre column get a small bonus. A forced win or loss scores ±100000, with a small bonus for winning sooner.

Alpha-beta pruning. Two bounds are passed down the tree. α is the best score MAX is already guaranteed on this path, and β is the best score MIN is already guaranteed. After each child, update them:

  1. At a MAX node, α ← max(α, score). At a MIN node, β ← min(β, score).
  2. If α ≥ β, stop looking at the remaining children (a cutoff). The other player would never allow this position, so those moves cannot change the final decision.

In the table, the window (α, β) is what the root passed into each move. Once a good move has raised α, later moves only need to prove they are no better, which is why they cost far fewer nodes and show a score that is only a bound (“≤ α”).

Why it works. Alpha-beta returns exactly the same best move as plain minimax, but skips branches that cannot matter. With perfect move ordering it searches about bd/2 nodes instead of bd, which lets it look about twice as deep in the same time. Try turning centre-first ordering off: the best moves are tried later, fewer cutoffs happen, and the node count goes up.
